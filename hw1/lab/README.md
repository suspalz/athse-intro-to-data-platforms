# Локальный стенд (Vagrant)

это не дз, но пусть клод расскажет

4 виртуалки в VirtualBox, которые имитируют выданную среду team-17. на нем проверены `INSTRUCTION.md` и `deploy.sh`

| ВМ | Адрес | Роль |
|---|---|---|
| `team-17-en` | 10.17.0.10 | edge |
| `team-17-nn` | 10.17.0.11 | namenode |
| `team-17-00` | 10.17.0.12 | datanode |
| `team-17-01` | 10.17.0.13 | datanode |

как в выданной среде:
- везде пользователь `team` с `sudo` без пароля, вход только по ключу
- снаружи пускает только на edge (ключ `keys/user_key`), на остальные ноды - с edge ключом `~/.ssh/team_internal`, он уже лежит на edge
- в `/etc/hosts` каждой ноды ее собственное имя для практики записано на `127.0.1.1` - та самая строка, из-за которой на семинаре подключалась 1 DataNode из 3

## Что нужно

- VirtualBox 7.0 (проверено на 7.0.18) и Vagrant 2.4 (проверено на 2.4.9)
- ~6 ГБ свободной оперативки: ВМ вместе занимают 5,5 ГБ
- интернет: при первом `vagrant up` скачается образ `bento/ubuntu-24.04`

## Ключи

ключей в репозитории нет, их надо создать один раз. PowerShell, из папки `lab`:

```powershell
mkdir keys
ssh-keygen -q -t ed25519 -N '""' -C user_key -f keys\user_key
ssh-keygen -q -t ed25519 -N '""' -C team_internal -f keys\team_internal
icacls keys\user_key /inheritance:r /grant:r "$($env:USERNAME):(R)"
icacls keys\team_internal /inheritance:r /grant:r "$($env:USERNAME):(R)"
```
- `user_key` - "ключ из анкеты": им заходим со своего компьютера на edge
- `team_internal` - ключ для прыжков с edge на остальные ноды, его копию стенд кладет на edge
- `-N '""'` - пустая парольная фраза. именно так, с кавычками внутри кавычек: обычный Windows PowerShell 5.1 теряет пустую строку `""`, и ssh-keygen падает с `Too many arguments` (в git bash и linux пишется просто `-N ""`)
- `icacls` - оставляем доступ к приватному ключу только себе, иначе ssh откажется им пользоваться (`UNPROTECTED PRIVATE KEY FILE`)

## Команды

все - в PowerShell из папки `lab`

| Что | Команда |
|---|---|
| создать и включить 4 ВМ (5–8 минут, в самый первый раз дольше - качается образ) | `vagrant up` |
| зайти на edge | `ssh -i keys\user_key team@10.17.0.10` |
| туннель к веб-интерфейсу NameNode | `ssh -i keys\user_key -L 9870:10.17.0.11:9870 team@10.17.0.10`, потом `http://localhost:9870` |
| выключить (все внутри сохраняется) | `vagrant halt` |
| удалить ВМ, чтобы начать с чистого листа | `vagrant destroy -f`, потом снова `vagrant up` |

- перед выключением компа делаем `vagrant halt`, после включения - снова `vagrant up`
- после пересоздания ВМ ssh может ругнуться `REMOTE HOST IDENTIFICATION HAS CHANGED` - у новой машины новый ключ, лечится `ssh-keygen -R 10.17.0.10`
- папку `.vagrant/` (там служебные приватные ключи vagrant) и `keys/` в git не кладем, они в `.gitignore`

## Чем стенд отличается от выданной среды

- `/etc/hosts` пишет `provision.sh` по образцу семинара: свое имя на `127.0.1.1`, остальные ноды по адресам. в выданной среде соседей может отдавать внутренний DNS
- минорная версия Ubuntu 24.04 может отличаться
- у каждой ВМ есть лишний сетевой интерфейс `10.0.2.15` (NAT от VirtualBox) и служебный пользователь `vagrant`
- скачивание и раздача hadoop могут идти дольше: шаг 6 у нас занимал от нескольких минут до 22
